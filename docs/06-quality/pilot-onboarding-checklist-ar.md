# قائمة تجهيز الشركة التجريبية

تُجمع هذه البيانات قبل بدء التجربة التشغيلية بأسبوع. يدخلها مسؤول النظام والموارد البشرية بأنفسهم من داخل البرنامج، بمساعدة [دليل المسؤول](../09-guides/admin-guide-ar.md). لا يوجد استيراد آلي، فالنظام يبدأ فارغًا حسب القرار DL-013.

**طريقة التسليم:** لا تُرسل بيانات الموظفين بالبريد أو بالمحادثات. تُدخل مباشرة في النظام، أو تُسلَّم في ملف محمي بكلمة مرور تُرسل بطريقة منفصلة.

## 1. قرارات قبل البدء (من المالك)

| # | القرار | الحالة |
|---|---|---|
| 1 | الدولة والمنطقة الزمنية للشركة التجريبية (Q-28) | ☐ |
| 2 | مدد الاحتفاظ بالبيانات (C-20) | ☐ |
| 3 | بيئة التجربة: الموقع الحالي، أو بيئة منفصلة على Railway (قد تكون لها تكلفة) | ☐ |
| 4 | جعل مستودع GitHub خاصًا (Private) | ☐ |
| 5 | تفعيل النسخ الخارجي (Backblaze)، وتنفيذ تجربة الاستعادة | ☐ |
| 6 | **حذف بيانات العرض التجريبية والحسابات التجريبية من الموقع قبل إدخال بيانات حقيقية** | ☐ |
| 7 | موافقة الموظفين المشاركين وإبلاغهم بسياسة الخصوصية (GDPR) | ☐ |

## 8. يوم الانطلاق

1. ☐ جلسة تعريفية لمدة 30 دقيقة لكل مجموعة: موظفون، ومديرون، وموارد بشرية ومالية.
2. ☐ كل موظف يدخل ويغيّر كلمة المرور، ويسجّل جهازه، ويفعّل الإشعارات.
3. ☐ أول بصمة حضور من المكتب.
4. ☐ توزيع [سيناريوهات الاختبار](pilot-test-scripts-ar.md) ونموذج الملاحظات.
5. ☐ اجتماع متابعة أسبوعي لمراجعة الملاحظات.
